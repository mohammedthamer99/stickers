# مخزن الاستيكرات

نظام بسيط لاستلام وتخزين وصرف استيكرات الأدوية. كل دفعة إلها: اسم المادة، الباج نمبر، تاريخ الانتهاء، مكان التخزين، الكمية، المصروف، والمتبقي. وكل حركة (استلام، صرف، تعديل) تنسجل بسجل الدفعة.

البيانات تنحفظ بقاعدة بيانات Postgres، يعني ما تنمسح بعد إعادة تشغيل أو نشر جديد.

**التقنيات:** Next.js 14 (App Router) + TypeScript + Postgres (`pg`).

## المميزات

- استلام دفعة جديدة. إذا نفس المادة والباج نمبر موجودين، الكمية تنضاف للدفعة الموجودة.
- إذا نفس الباج نمبر بتاريخ انتهاء مختلف، النظام يرفض ويقولك.
- سحب مادة مع بحث (بالاسم أو الباج نمبر أو المكان)، والقائمة مرتبة بالأقرب انتهاءً أول.
- زر «صرف» على كل دفعة، وسجل حركات، وتعديل وحذف.
- تنبيه للدفعات القريبة من الانتهاء (90 يوم) والمنتهية.
- الصرف ينفذ داخل قاعدة البيانات بشكل آمن، فلو شخصين صرفوا بنفس اللحظة ما يصير المتبقي بالسالب.
- دخول بكلمة سر وحدة.

## تشغيل المشروع على جهازك

تحتاج Node.js 20 أو أحدث وقاعدة Postgres.

```bash
npm install
cp .env.example .env.local     # عدّل القيم داخل الملف
npm run dev
```

بعدها افتح `http://localhost:3000`.

الجداول تنشأ لوحدها أول ما يشتغل النظام، ما تحتاج تسوي شي يدوي.

## الإعدادات (Environment Variables)

| الاسم | شنو يسوي |
| --- | --- |
| `DATABASE_URL` | رابط قاعدة Postgres |
| `APP_PASSWORD` | كلمة السر اللي تدخل بيها للنظام |
| `AUTH_SECRET` | اختياري. نص عشوائي طويل لتوقيع جلسة الدخول. إذا تركته فارغ تنستخدم `APP_PASSWORD` |

## الخطوة 1: قاعدة البيانات (مجانية)

اختار واحدة منهم:

**Neon** (الأسهل مع Vercel)
1. سوّي حساب على neon.tech وأنشئ Project.
2. من صفحة المشروع اضغط **Connect** وانسخ الـ **Connection string** (يفضل النسخة اللي بيها pooler).
3. هذا هو `DATABASE_URL`.

**Supabase**
1. أنشئ Project من supabase.com.
2. من **Connect** انسخ الـ **Transaction pooler** connection string وبدّل `[YOUR-PASSWORD]` بكلمة سر القاعدة.
3. هذا هو `DATABASE_URL`.

## الخطوة 2: الرفع على GitHub

أنشئ repository فاضي على GitHub (خليه **Private**)، وبعدين من مجلد المشروع:

```bash
git init
git add .
git commit -m "مخزن الاستيكرات"
git branch -M main
git remote add origin https://github.com/USERNAME/stickers-inventory.git
git push -u origin main
```

الملف `.gitignore` يمنع رفع `.env.local`، فكلمات السر ما تنرفع.

## الخطوة 3: النشر على Vercel

1. من vercel.com اضغط **Add New → Project** واختار الـ repository.
2. قبل ما تضغط Deploy افتح **Environment Variables** وضيف:
   - `DATABASE_URL`
   - `APP_PASSWORD`
   - `AUTH_SECRET` (اختياري)
3. اضغط **Deploy**.
4. افتح الرابط واكتب كلمة السر. أول فتح ينشئ الجداول تلقائياً.

بعد هذا، كل `git push` على `main` ينشر نسخة جديدة، والبيانات تبقى محفوظة لأنها بقاعدة البيانات مو بالمشروع.

إذا تريد السيرفر قريب من القاعدة، اختار نفس المنطقة بإعدادات Vercel (Settings → Functions → Region) حتى يصير النظام أسرع.

## ملاحظات

- **كلمة السر:** هي كلمة وحدة مشتركة لكل الموظفين. إذا تريد حسابات منفصلة لكل موظف (ومن سوّى كل حركة)، هذا يحتاج تطوير إضافي.
- **تغيير كلمة السر:** غيّر `APP_PASSWORD` من إعدادات Vercel واعمل Redeploy. كل الجلسات القديمة تنتهي إذا ما حطيت `AUTH_SECRET` ثابت.
- **النسخ الاحتياطي:** Neon وSupabase يوفرون نسخ احتياطية حسب الخطة. تكدر تصدّر القاعدة بأي وقت بـ `pg_dump`.
- **الحماية:** النظام يقفل كل الصفحات والـ API بدون تسجيل دخول، لكن ما بيه حد لمحاولات الدخول الغلط. إذا النظام بيطلع على الإنترنت للعموم وتريد حماية أكثر، ضيف rate limiting أو ربطه بـ Vercel Firewall.

## هيكل المشروع

```
  app/
    page.tsx                      الصفحة الرئيسية
    login/page.tsx                صفحة الدخول

  lib/inventory.ts                منطق الاستلام والصرف (transactions)
  lib/validate.ts                 التحقق من المدخلات
  lib/auth.ts, middleware.ts      الحماية بكلمة السر
schema.sql                        شكل الجداول (مرجع)
```
